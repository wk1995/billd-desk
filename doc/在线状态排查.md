# 设备一直显示「不在线」排查说明

> 最后更新：2026-10-29
> 相关分支：`local-mac-backend`
> 后端：`http://100.70.34.72:4300`（Mac + Tailscale）

## 一、先看结论

主控端提示「该设备不在线」**不代表网络不通**，它只取决于一个接口：

```
GET /desk_user/find_receiver_by_uuid?uuid=<设备代码>
→ {"code":200,"data":{"receiver":""}}      // 不在线
→ {"code":200,"data":{"receiver":"<socketId>"}}  // 在线
```

`receiver` 有值的前提是：**被控端客户端**连上 socket.io 后，成功发送 `billdDeskJoin`，
并且服务端把它的 socket 登记到 `deskUserUuid` 下。

所以排查顺序永远是：**被控端设备信息 → socket 连接 → join 是否带上设备代码 → 服务端是否登记**，
而不是先去查网络。

## 二、完整链路

```
remote 页面 mount
  └─ initDeskUser()            有缓存则 /desk_user/login，无缓存则 /desk_user/create
       └─ roomId = cacheStore.deskUserUuid
  └─ initWs({ roomId })        new WebSocketClass → io(ws://100.70.34.72:4300)
       └─ socket 'connect'
            └─ sendJoin()      emit billdDeskJoin { deskUserUuid, deskUserPassword, live_room_id }
                 └─ 服务端回 billdDeskJoined
                      └─ 服务端把 socket 登记到 deskUserUuid → find_receiver_by_uuid 才有值
```

主控端点击「连接」时只做一件事：调 `find_receiver_by_uuid`，返回空就提示不在线。

## 三、2026-10-29 已定位并修复的问题

**问题**：`src/views/remote/index.vue` 里 `const { initWs, connectStatus } = useWebsocket();`
只解构了两个返回值，**从未把 `cacheStore.deskUserUuid / cacheStore.deskUserPassword`
回填给 `useWebsocket()` 内部的同名 ref**。

于是 `use-websocket.ts` 的 `sendJoin()` 发出的是：

```js
{ deskUserUuid: '', deskUserPassword: '', live_room_id: 'Ruh9M46L' }
```

服务端照样回 `billdDeskJoined`（所以界面完全不报错），但不会把 socket 登记到该设备代码下，
`find_receiver_by_uuid` 永远返回空 → 一直显示「该设备不在线」。

**实测对照**（node + socket.io-client 模拟 join，2.5s 后查询）：

| join 内容 | 是否收到 joined | find_receiver_by_uuid |
| --- | --- | --- |
| `deskUserUuid` + 正确密码 + `live_room_id` | 是 | 返回 socketId ✅ |
| `deskUserUuid: ''` + `deskUserPassword: ''` + 正确 `live_room_id` | 是 | 返回空 ❌ |

**已修复**：`src/hooks/use-websocket.ts` 的 `sendJoin()` 改为
`deskUserUuid.value || cacheStore.deskUserUuid`，密码同理；uuid 仍为空时打日志并放弃本次 join。

> `webrtc` 页面因为从 `route.query` 赋了值，所以那条路径一直是正常的，问题只在 `remote` 页面。

## 四、本次新增的诊断能力

### 1. 统一日志前缀 `[desk-debug]`

控制台过滤 `desk-debug` 即可看到整条链路，每一步都带上下文。

| 日志 step | 含义 | 关键字段 |
| --- | --- | --- |
| `initDeskUser 开始` | 开始准备设备信息 | `mode`（create/login）、脱敏后的 uuid/密码 |
| `create 设备结果` / `login 设备结果` | 接口返回 | `code`、`message` |
| `initDeskUser 完成` | 设备信息是否就绪 | `roomId`、`state`、`hint` |
| `initDeskUser 异常` | login 校验失败（400 会走 catch） | `error` |
| `initWs 开始连接` | 开始建 socket | `roomId`、`url` |
| `initWs 警告：roomId 为空` | 设备信息没准备好 | 脱敏后的 uuid/密码 |
| `socket 已连接，准备 join` | ws 已通 | `socketId`、`url` |
| `发送 billdDeskJoin` | join 已发出 | 脱敏信息、`liveRoomId`、`uuidFrom`、`socketId` |
| `sendJoin 跳过 / sendJoin 失败` | join 没发出去 | 失败原因、`wsMapKeys` |
| `服务端已确认 joined` | 服务端已回执 | `liveRoomId`、`receiver` |
| `socket 已断开` / `socket 连接失败，正在重试` | 连接异常 | `url`、`reason`/`message` |
| `查询设备是否在线（find_receiver_by_uuid）` | 主控端查询结果 | `uuid`、`code`、`receiver` |
| `设备不在线：服务端没有该设备代码对应的 socket 登记` | 查询为空 | `uuid`、`selfUuid`、`hint` |

密码只输出「已设置(长度N)」或「(空)」，不会把临时密码写进日志。

### 2. 状态机 `DeskJoinStateEnum`

定义在 `src/types/websocket.ts`，由 `useWebsocket()` 暴露为 `deskJoinState`：

```
idle → preparingUser → userReady → wsConnecting → wsConnected → joinSent → joined
                └→ prepareUserFailed              └→ joinFailed
                                                  └→ wsDisconnected（重连后回到 wsConnected）
```

| 状态 | 含义 | 说明 |
| --- | --- | --- |
| `idle` | 未开始 | 页面刚加载 |
| `preparing-user` | 正在 create/login | — |
| `prepare-user-failed` | 设备信息不可用 | login 失败或 uuid 为空，**根本原因通常在这一步** |
| `user-ready` | 设备信息就绪 | `roomId` 已有值 |
| `ws-connecting` | socket 连接中 | 连不上时状态会反复停留在这里 |
| `ws-connected` | socket 已通 | 紧接着会 sendJoin |
| `join-sent` | join 已发出 | 等 `billdDeskJoined` |
| `joined` | 服务端已确认 | **此时主控端必须能查到 receiver** |
| `join-failed` | join 没发出去 | socket 实例缺失或 uuid 为空 |
| `ws-disconnected` | 连接断开 | 服务端会认为设备下线 |

在 remote 页面连点 5 次开启 debug 面板（`appStore.showDebug`），可直接看到
`join状态` / `ws状态` / `roomId` / `socketId`。

## 六、如果状态到 joined 但依然查不到

说明客户端已经按协议发对了，问题在服务端 `billdDeskJoin` 的处理：

- 服务端是否用 `deskUserUuid` 作为登记 key（而不是 `live_room_id`）；
- 是否在 `socket.on('disconnect')` 时正确地删除登记；
- 是否存在多进程/集群导致登记在 A 进程、查询打到 B 进程（内存 Map 不共享）；
- 服务端是否对 `deskUserPassword` 做了额外校验并静默失败。

建议服务端在 `billdDeskJoin` 成功登记后补一条日志：
`join ok uuid=<deskUserUuid> socket=<socket.id> room=<live_room_id>`，
以及在 `find_receiver_by_uuid` 返回空时打印查询的 key，便于两侧对齐。

## 七、常见误判：设备代码会变

设备代码（`deskUserUuid`）不是固定的，下列情况会重新 `create` 一个新代码：

- 点击「此设备」旁的刷新按钮（`handleResetDeskuuid` 会清空缓存后重新 create）；
- localStorage 丢失（清缓存、重装、换构建产物）；
- dev 模式下 Vite 端口变化（`localhost:5173` 与 `5174` 属于不同 origin，localStorage 不互通）。

判断方法：被控端界面「此设备」显示什么，就用什么。历史上用过的旧代码在服务端仍然存在
（`login`/`join` 都能通过），但永远不会有 socket 在线，查到的一定是空。

## 八、附：手动模拟 join 的排查脚本

```js
// node test/check-join.mjs <uuid> <password> [empty]
// empty 模式会模拟「前端发空 deskUserUuid」的历史 bug
import { io } from 'socket.io-client';

const BASE = 'http://100.70.34.72:4300';
const [TARGET, PWD, MODE] = process.argv.slice(2);
const socket = io(BASE, { transports: ['websocket'] });

socket.on('connect', () => {
  const data = MODE === 'empty'
    ? { deskUserUuid: '', deskUserPassword: '', live_room_id: TARGET }
    : { deskUserUuid: TARGET, deskUserPassword: PWD, live_room_id: TARGET };
  socket.emit('billdDeskJoin', {
    request_id: 'check123',
    socket_id: socket.id,
    user_info: {},
    user_token: '',
    time: Date.now(),
    data,
  });
});

socket.onAny((event, ...args) => console.log('[recv]', event, args));

setTimeout(async () => {
  const res = await fetch(`${BASE}/desk_user/find_receiver_by_uuid?uuid=${TARGET}`);
  console.log('[find_receiver_by_uuid]', await res.text());
  socket.close();
  process.exit(0);
}, 2500);
```
